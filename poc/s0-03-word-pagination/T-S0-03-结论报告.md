## 四、技术方案设计（已验证）

### 4.1 核心链路

```
docx → soffice --headless --convert-to pdf → PDF
PDF → pdfplumber.extract_text(页级) → 每页文本
每页文本 ∩ 段落锚点 → page_of_anchor[锚点] = 页码
docx paragraphs → para_index → 对应页码 → LocationSelector{page, paraIndex}
```

### 4.2 锚点策略

在产品层面，"段落唯一 ID"由以下两种方式之一提供：

1. **写入时注入**（改写 PoC 时已用）：改写前在每段末尾写入不可见 Unicode 私用区字符（U+E000~U+F8FF）作为段落 ID，改写后定位对应 ID。
2. **内容指纹**（只读场景）：对每段文本取前 20 字符 + 长度哈希，在 PDF 文本中匹配前缀，适用于不可修改的原始文档。

两种方式均已由本 PoC 的锚点匹配逻辑验证可行。

## 五、已知局限与降级策略

| 场景 | 风险 | 降级策略 |
| --- | --- | --- |
| 含分栏布局（多列）| PDF 文本提取顺序可能按视觉列序，锚点定位偏差 | 降级为段落索引定位（放弃精确页码），回退到 §3.7 段落 diff 模式 |
| 超长表格跨页 | 表格行在 PDF 中无段落边界，无法锚点化 | 以表格为整体映射到首行所在页；复杂改写绕过表格内部页定位 |
| 极密集段落（单段 > 1 页）| 锚点只能映射到首现页，后续页内容无法细分 | 段落内改写走词级 diff（T-S0-04 已验证），不依赖页级定位 |
| LibreOffice 字体缺失 | 中文字体未嵌入时排版偏差影响页边界 | 打包时随包嵌入项目所需字体子集（约 2-5 MB），或指定 --convert-to pdf:writer_pdf_Export:EmbedStandardFonts=true |

本次测试的 complex.docx（含页眉/页脚）已覆盖最常见"复杂"场景，准确率 100%，无需触发降级。
