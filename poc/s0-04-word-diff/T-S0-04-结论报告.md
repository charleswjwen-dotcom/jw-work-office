## 二、AtomicChange 结构对齐（§3.7）

PoC 产出的 `AtomicChange` 与架构文档 §3.7 定义一一对齐：

```
{ id, location:{type:'paragraph', index}, order, kind, before?, after?, renderHint }
```

- `id`：稳定单条 id（`ac-001`…），供部分接受勾选。
- `location.index`：**统一锚定在 before 序列的段落下标**（关键设计，见第三节）。
- `kind`：`text`（替换）/ `insert`（新增）/ `delete`（删除），由 LCS 回溯 + 相邻替换合并得出。
- `before`/`after`：结构化载荷（`{text}`），diff 渲染只消费该结构，**不做整文件文本对比**（对齐 §3.7 核心原则）。
- `order`：新增字段，用于同一锚点上多条变更的稳定排序（保证 apply 顺序确定）。

---

## 三、关键设计决策（供架构 v1.3 参照）

1. **index 统一锚定 before 序列**：所有变更（含 insert）的 `location.index` 均以 before 序列的段落下标为锚点，避免 insert 用 after 下标导致 apply 定位错乱。相邻的 delete+insert 复用同一锚点，从而能合并为一条 `text` 替换。

2. **apply 采用「按锚点分组 + 从后往前 splice」**：同锚点变更按 `order` 排序后成组应用，从大到小遍历锚点，保证前面的 splice 不影响后面锚点的下标，天然稳定。

3. **回滚 = 反向重新 diff**：`invertChanges(after, before)` 直接 `computeParagraphDiff(after, before)`，而非机械反演单条变更。这与 index 语义自洽，且正是生产 ChangeSet 回滚的真实路径（§5 快照回溯）。

4. **两级 diff 粒度**：段落级 diff（结构变更）+ run/词级内联 diff（`renderInlineDiff`，同段落内高亮增删词）。Word 富文本内联高亮走此路径，复杂排版可降级 side-by-side（对齐 §3.7 渐进增强）。

5. **计算/渲染分离**：diff 计算（`diff_engine.js`）为纯函数，可运行于主进程；渲染（`diff_renderer.js`）只产出 HTML，符合 §3.7「diff 计算在主进程、渲染进程只展示」。

## 四、对三格式 diff 架构的参照价值

本 PoC 作为 §3.7 三格式 diff 的**参照实现**，为后续对齐提供样板：

- **Excel**：`location` 改为 `{type:'cell', addr}`，`before/after` 为 `{value, style}`，复用同一 apply/回滚框架（分组键换成单元格地址）。
- **PPT**：`location` 改为 `{type:'element', slide, shapeId}`，S2 先做整页并排（规避 EMU→像素映射），apply/回滚框架不变。
- 三格式共享：`AtomicChange` 结构、部分接受（`accepted`）、回滚（反向 diff）、计算/渲染分离。
