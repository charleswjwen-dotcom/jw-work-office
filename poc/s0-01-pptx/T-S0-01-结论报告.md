## 关键技术发现

### onefile vs onedir

| 打包模式 | 体积 | 首次冷启动 | 第 2+ 次启动 | 结论 |
| --- | --- | --- | --- | --- |
| `--onefile` | 14 MB | ~4.6 s | ~4.6 s（每次解压） | ❌ 不可用 |
| `--onedir` | 33 MB | ~4.7 s（Gatekeeper 首检） | ~80 ms | ✅ 选定方案 |

**必须使用 `--onedir` 模式**。`--onefile` 每次运行都把 bundle 解压到临时目录，导致每次调用都是 4.6 s 冷启动，完全不满足延迟要求。`--onedir` 首次加载后进入 OS 页缓存，后续 80 ms。

### 进程池预热策略（对应架构 §3.4）

首次冷启动 4.7 s 来自 macOS Gatekeeper 对未经正式签名的二进制进行首检，正式 Developer ID 签名 + 公证后这一耗时会显著缩短（通常 < 1 s）。

无论如何，Electron 侧**必须在应用启动时预热 Python 进程**（与 LibreOffice 进程池同一模式），请求到来时直接使用已驻留进程，热路径延迟 ≤ 500 ms（实测 136 ms 均值）。

## 架构决策更新（待写入 §3.4 v1.3）

1. **打包方式**：PyInstaller `--onedir`，不用 `--onefile`。
2. **进程管理**：Electron Utility 进程启动时预热 Python 进程池（≥1 实例），调用通过 child_process stdin/stdout JSON-RPC。崩溃后按 §3.4 自愈策略重启。
3. **体积基线**：python-pptx 运行时增量约 33 MB，加入安装包体积估算。
4. **待补验证**：正式 Developer ID 签名 + notarytool 公证（S2 前置）；Windows 流程（S2 前置）。
